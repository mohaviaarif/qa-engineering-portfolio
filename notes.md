# Notes

**Testing vs debugging:**

Testing is checking for a bug or defect in a product and then telling the relative person to solve that on the other hand is debugging is finding the root cause of the bug or defect and solving that. In static testing we just found a bug and solve it while in dynamic testing we firstly reproduce the error then we do diagnosis to find what is the cause then we fix the error.

**Objectives of testing:**

- To find defects
- To provide information so someone else can fix it.
- To build confidence
- To give information to stakeholder so they can make inform decisions
- Evaluating work products to check user stories, design, code and requirements
- Ensuring proper coverage of test object
- Reduce the risk of bad quality product
- Checking whether requirements is fulfilled
- Checking if test object follows legal, contractual and regulatory requirements
- Validating whether test object work as expected

**7 Principles of testing**

1. Testing proves presence not absence of defect
2. Testing all the things is not possible
3. We cannot say that after testing the product will succeed
4. Early testing is beneficial
5. Defects are usually present in a cluster
6. Test wears out
7. Testing is context dependent

**Test types**

- Functional testing
- Non-functional testing
- Black box testing
- White box testing
- Change-related testing(Regression and Confirmation Testing)

**Test Levels**

- Component testing
- Component integration testing
- System Integration testing
- System testing
- Acceptance testing

**Defect Lifecycle**

Finding-Logging-communication-solving-retesting-ending
